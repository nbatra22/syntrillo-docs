## Architecture: Before vs. After

<CardGroup cols={2}>
  <Card icon="server" title="Current System (Live)">
    **Frontend:** HTML/CSS rendered server-side via Flask templates

    **Backend:** Flask on PythonAnywhere — handles routing, rendering, and  logic in one process

    **Database:** AWS (MySQL via pymysql)

    **Auth:** Session-based, handled in Flask
  </Card>
  <Card icon="arrows-rotate" title="New System (In Progress)">
    **Frontend:** React 19 + TypeScript + Vite — runs in the browser, fetches data via  API

    **Backend:** FastAPI + Uvicorn, no HTML rendering

    **Database:** Same AWS MySQL (shared `sources/syntrillo` layer)

    **Auth:** ??
  </Card>
</CardGroup>

---

## Migration Plan

**Phase 1 — API layer (ongoing)** Port all Flask routes to FastAPI. Each old route becomes one or more focused REST endpoints that return JSON. No HTML is returned from the API.

**Phase 2 — Frontend (ongoing)** Build the React-TS frontend to consume the new API. The React app replaces all Jinja templates and Flask-rendered iframes. Components are organized by feature (BP tab, risk score, etc.).

**Phase 3 — Deployment** Lambda functions for webhook triggers to update databases and stroke risk score. Each page deployed separately.
