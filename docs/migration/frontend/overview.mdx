## Overview

The new frontend is a React 19 + TypeScript application built with Vite, located at `apps/React-TS/`. It replaces all Flask-rendered HTML templates and Jinja iframes. The app runs entirely in the browser and fetches data from the FastAPI backend.

## App Structure

```text
apps/React-TS/src/
├── main.tsx              # Entry point — renders <App /> into the DOM
├── App.tsx               # Root component, router setup
├── App.css
├── index.css             # Tailwind base styles
├── pages/
│   ├── login/            # Login page
│   ├── patient-sidebar/  # Patient-facing sidebar view
│   ├── provider-sidebar/ # Provider-facing sidebar view
│   └── provider-tab/     # Provider tab views (BP, risk score, etc.)
├── components/
│   ├── auth/             # Auth-related components
│   ├── inputs/           # Shared input components
│   ├── patient-sidebar/  # Components for the patient sidebar page
│   ├── provider-sidebar/ # Components for the provider sidebar page
│   └── provider-tab/     # Components for the provider tab pages
├── utils/                # Shared utilities and API client helpers
└── assets/               # Static assets
```

## Pages

**Provider Tab** — The main clinical view. Loads data from the FastAPI API and renders the BP tab, risk score tab, and other clinical panels. Corresponds to the legacy Flask iframes that were embedded in Healthie.

**Provider Sidebar** — Provider-facing patient list and navigation.

**Patient Sidebar** — Patient-facing view showing their own data.

**Login** — Authentication entry point.

---

## API Integration

The React app fetches data from the FastAPI backend (`http://127.0.0.1:8000/api/v1/...` in development). A key design advantage over the legacy system: the frontend can fetch multiple endpoints **in parallel** rather than waiting for a single large response.

For example, the BP tab can simultaneously fetch `/summary`, `/analysis`, `/extremes`, and `/distribution` using `Promise.all`, reducing total load time compared to the legacy single-payload approach. Planning on making this event driven
